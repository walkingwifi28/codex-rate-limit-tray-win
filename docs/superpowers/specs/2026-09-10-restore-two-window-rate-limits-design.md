# 5時間枠・週次枠の2枠表示復元 設計

## 背景

Codexの利用状況レスポンスは現在、`rate_limit.primary_window` に5時間枠、`rate_limit.secondary_window` に週次枠を返している。現行アプリは週次枠対応時の変更で `primary_window` を週次枠として扱い、`secondary_window` を破棄しているため、5時間枠を「週」と誤表示し、週次枠を表示できない。

## 目的

- 5時間枠と週次枠を同時に取得・保持・表示する。
- 5時間枠のリセット時刻と週次枠のリセット時刻をそれぞれ表示する。
- 既存のトレイアイコン、ポップアップ、ツールチップの2枠表示を復元する。
- `secondary_window` が欠ける旧レスポンスでは、取得済みの枠を保持して異常終了しない。

## データモデルとデータフロー

`UsageState` に必須の `FiveHour` と nullable な `Week`（`UsageWindow?`）を持たせる。nullable は「今回のレスポンスに週次枠がない」ことだけを表し、前回の成功値を保持するキャッシュは導入しない。

1. `WhamUsageParser` が `primary_window` を5時間枠として読む。
2. `secondary_window` がオブジェクトなら週次枠として読む。
3. `secondary_window` が `null` または存在しない場合は `Week = null` とする。
4. `secondary_window` が存在するのにオブジェクトでない、または `used_percent` / `reset_at` が欠落・不正な場合は、レスポンス全体を `InvalidResponse` とする。
5. `primary_window` が欠落・null・不正な場合も、レスポンス全体を `InvalidResponse` とする。
6. UIは5時間枠と週次枠を独立して描画し、週次枠がない場合でも5時間枠を表示する。
7. JSONが不正、トップレベルがオブジェクトでない、または必須プロパティへアクセスできない場合は、レスポンス全体を `InvalidResponse` とする。

`used_percent` は有限な数値として読み、表示とリング描画の両方で0〜100にクランプする。`reset_at` は必須のUnix秒整数で、Unix epochはUTC基準とする。`limit_window_seconds` などの補助フィールドは読み飛ばす。APIクライアントの認証、HTTPエラー分類、更新間隔も変更対象外とする。

## 表示仕様

- ポップアップは常に2行分の高さを確保し、上段に「5時間」、下段に「週」を表示する。
- `reset_at` はパーサーに渡されたローカル `TimeZoneInfo` で変換する。5時間枠は残り率とローカル時刻（InvariantCultureの`HH:mm`、先頭ゼロあり）を表示する。
- 週次枠は残り率とローカル日付・時刻（InvariantCultureの`MM/dd HH:mm`、先頭ゼロあり）を表示する。
- ツールチップは `Codexレート制限 : {5時間残り率}% / {週次残り率}%` の形式で両方を併記する。週次枠がない場合は完全に `Codexレート制限 : {5時間残り率}% / -` とする。
- アイコンは外側を週次枠、内側を5時間枠として2重リングで表示する。外側は `#339CFF`、内側はライトテーマで `#1A1C1F`、ダークテーマで `#FFFFFF` とする。週次枠がない場合は外側を描画せず、5時間枠だけを描画する。
- リングの扇形はクランプ後の `used_percent` を描画し、12時方向（`-90°`）から時計回りに使用率分だけ塗る。0%は使用色の扇形なし、100%は円全体を使用色で塗る。未使用領域は透明とする。
- 週次枠がない場合は週次行の6ラベルすべてを空文字にして空欄にし、エラーにはしない。5時間枠が不正な場合、または週次枠が存在して不正な場合は既存のエラー表示を使う。
- 週次リセット時刻の進捗針は、週次枠が存在する場合だけ従来どおり外側リングに描画する。

## 代替案と選択理由

### 案A: 以前の2枠実装を復元する（採用）

既存の履歴にある2枠モデル、表示レイアウト、リング描画を復元し、`secondary_window` の欠落だけを防御的に扱う。変更範囲が小さく、既存UIの意図とテストを再利用できる。

### 案B: ウィンドウを可変長コレクションで表示する

APIの枠数には柔軟だが、現在の2枠だけのUIに対してモデル・レイアウト・テストが過剰になるため採用しない。

### 案C: APIレスポンスのウィンドウ秒数で枠名を動的判定する

将来の順序変更には強いが、現行APIの意味が明確で、既存コードの復元より変更量と不確実性が増えるため採用しない。

## テスト方針

- `primary_window` と `secondary_window` の両方があるJSONから、5時間枠と週次枠を正しく分離するテストを追加する。
- `secondary_window: null` およびキー欠落のレスポンスで、5時間枠を保持しつつ `Week = null` でエラーにしないことをテストする。
- `secondary_window` の不正型・必須フィールド欠落、`primary_window` の欠落・不正値を `InvalidResponse` とすることをテストする。
- malformed JSON、トップレベルが配列・文字列・null、`primary_window` / `secondary_window` のnull・型違い・キー欠落、`reset_at` が `DateTimeOffset` のUnix秒範囲外のケースを `InvalidResponse` とすることを個別にテストする。
- `used_percent` の文字列・真偽値・JSONとして非有限な値を不正として扱い、有限な数値の負値・100超は表示とリングの双方で0〜100にクランプされることをテストする。
- UTCなど固定した `TimeZoneInfo` を使い、表示フォーマッターとポップアップの完全一致文字列（`5時間`は`HH:mm`、`週`は`MM/dd HH:mm`のテンプレートに従う）をテストする。`CurrentCulture` を一時的にInvariantCulture以外へ変更しても、先頭ゼロを含む同じ文字列になることを検証し、Unix epochのUTC基準とTokyoの固定値によるローカル変換も検証する。
- ツールチップは両枠ありで `Codexレート制限 : 75% / 20%`、週次枠なしで `Codexレート制限 : 75% / -` の完全一致を検証し、週次枠欠落時の空行とポップアップの2行レイアウトもテストする。
- アイコンの外側・内側リングが別のクランプ済み `used_percent` を反映し、週次枠欠落時は内側だけになることをテストする。0%・100%・範囲外値の境界では、それぞれ使用色の扇形なし・円全体・クランプ後の描画になることをテストする。50%のリングについて12時方向と3時方向が使用色、9時方向が未使用領域になるサンプルを検証し、12時開始・時計回りを固定する。
- 既存のHTTPエラー・認証・残り率計算テストを維持する。

## 非対象

- Codex APIのエンドポイント変更
- 利用枠の推定値やリセット時刻の補正
- 更新間隔やWindows起動設定の変更
- 新しい配布版のリリース、署名、WinGet manifestの更新
